TIMBRE STUDIO / QUEUE DESIGN

Queue halisi, kwa hatua.

Ripoti ya Hermes: n8n + Caddy zipo kwenye EC2; n8n inatumia SQLite, na RAM inayopatikana ni takriban 787 MB wakati wa kipimo. Hii ni picha ya wakati mmoja, si uwezo wa kudumu.

Usi-install wala ku-activate bado.

Faili n8n/queue/01-schema.sql na n8n/queue/echo-queue-test.json ni prototype ya echo pekee. Workflow imepimwa kwenye n8n ya ndani ya majaribio pekee; hakuna chochote kilichounganishwa kwenye VPS au dashboard. Hii si workflow ya production.

Muundo unaopendekezwa

Timbre → API salama (baadaye) → n8n → Postgres queue tofauti → n8n webhook → PC worker → n8n → queue. n8n itaendelea kutumia SQLite yake; hatuigusi wala kuihamisha.

Postgres ni pendekezo kwa sababu tunaweza kuhifadhi hali ya kazi na kudai kazi kwa atomic transaction. SQS ni mbadala wa managed usiotumia RAM ya database kwenye VPS, lakini bado tutahitaji kushughulikia historia/status, idempotency, IAM na gharama. Bei na free tier hutegemea akaunti/region/matumizi; si salama kuahidi ni bure.

VideoFactory na PC worker

VideoFactory ndiyo renderer inayopangwa kutumika; hatujajenga renderer yake upya. Worker sasa ina check ya hiari videofactory_check ambayo mmiliki wa PC huiwezesha kwa kuweka TIMBRE_VIDEOFACTORY_ROOT kwenye environment ya worker. Inasoma mafaili maalum ya code na hali ya JSON, na inarudisha flags tu; haifungui web server, haisomi .env, na hairender wala kupost. Job haiwezi kuchagua folder.

Bado haijaunganishwa: queue prototype inaruhusu echo tu, kwa hiyo haiwezi kutuma check hii bado. Render, probe na concat zimezimwa kwa remote jobs mpaka ulinzi wa filesystem na idempotency ukamilike. Worker mpya na video-factory-check.mjs vyote vinahitajika kwenye PC.

Mzunguko wa kazi

  1. Queued: kazi inaingia queue na ID yake. Kuanza, tunaruhusu echo tu.
  2. Leased: PC inadai kazi kupitia n8n. Database inaipa lease ID na muda wa kuisha. Claim hutumia row lock ili madai ya wakati mmoja yasipewe lease ileile.
  3. Completed: PC inarudisha job ID, lease ID na matokeo; n8n inakubali tu lease inayolingana na haijaisha. Ujumbe uleule wa matokeo ukirudiwa baada ya kuandikwa unakubaliwa bila kubadilisha matokeo.
  4. Lease ikiisha: kazi inaweza kudaiwa tena. Hii ni at-least-once: PC ya kwanza inaweza bado kufanya kazi, kwa hiyo haihakikishi kazi imeendeshwa mara moja tu. Echo haina side effects; render/upload zitahitaji heartbeat, idempotency na ulinzi wa output kabla ya kuruhusiwa.

Kwa Hermes / Antigravity: maandalizi salama

  1. Usibadilishe chochote bado. Angalia backup iliyopo kama kweli inarun, kama inajumuisha n8n database na encryption key, na kama restore imewahi kujaribiwa. Usiandike keys, token, database contents au env kwenye chat.
  2. Tengeneza pendekezo la deployment na makadirio ya gharama; hatutoi ahadi ya 100% safe. Postgres 16 ARM64, persistent volume, network ya ndani tu bila host/public port, health check, least-privilege DB user, na secrets zisizo kwenye Git.
  3. Weka mpango wa backup na restore ya database mpya, rollback na ufuatiliaji wa RAM/swap/disk. Memory limit ni kinga tu, si uthibitisho kwamba 256 MB inatosha au kwamba n8n haiathiriki. Pima mzigo kabla ya production.
  4. Baada ya review na idhini ya mmiliki, tumia mazingira ya test kwanza. Usibadilishe DB ya n8n au kutoa huduma iliyopo.

Kabla ya kupima na PC

  • Workflow ya majaribio ipo kwenye n8n/queue/echo-queue-test.json: ina webhook mbili za Header Auth na SQL parameters, imepimwa kwenye n8n 1.121.3 ya ndani; inahitaji kupimwa kwenye mazingira yaliyotengwa yenye version ya VPS kabla ya deployment. Usihifadhi token kwenye workflow JSON.
  • Worker wa repository sasa anarudisha leaseId na anahitaji accepted: true kwa kazi yenye lease. Toleo la zamani la handshake kwenye PC halitumii lease: update worker kabla ya queue test.
  • Pima database halisi: claims mbili sambamba, queue tupu, lease expiry, stale result, duplicate result, restart na restore. Muda wa expiry wa echo ni dakika tano; si wa video render.
  • Linda execution logs: webhook headers zinaweza kuwa na token. Punguza retention na access; kamwe usizitumie kama sehemu ya majibu au kuzipaste kwenye chat.
  • Dashboard drafts bado ni local browser tu. Kuunganisha planner kunahitaji API yenye uthibitishaji, authorization na idempotency; usipe browser token ya worker au credentials za database.

Uthibitisho wa sasa: Schema imepimwa kwenye PostgreSQL 16.15 ya muda kwenye sandbox: lock ya transaction ya pili, queue tupu, expiry, stale result na duplicate acknowledgement. Worker na validation zimepita unit tests. Kazi iliyowekwa kwenye queue ilinusurika clean restart ya PostgreSQL kwenye local test. Pia n8n 1.121.3 ya ndani, worker na PostgreSQL zimekamilisha echo round-trip; queue tupu, stale lease, duplicate result na ombi bila token zimepimwa. Hii haijapimwa kwenye n8n ya VPS au PC ya mtumiaji; backup/restore bado haijajaribiwa. Hakuna mabadiliko yaliyofanywa kwenye VPS.
